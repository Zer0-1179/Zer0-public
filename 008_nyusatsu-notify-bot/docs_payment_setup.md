# 決済（Stripe）導入ガイド

## 方針

自前の決済システムは開発せず、**Stripe Payment Links**（ノーコード）を使う。月額課金の請求・カード失敗時の再試行・領収書発行・解約処理はすべてStripe側に任せる。

## ユーザー自身が行う必要がある作業（Claudeでは代行不可）

Stripeアカウント作成には本人確認（KYC）・銀行口座登録・事業者情報の入力が必要で、これは口座名義人本人の情報を要するため自動化できない。以下はユーザー側の作業。

1. [Stripe](https://stripe.com/jp) でアカウント作成（メールアドレスのみで開始可能）
2. 事業形態を「個人（個人事業主）」で選択し、氏名・住所・事業内容（情報通信業/SaaS等）・サービスURL（`https://nyusatsu.zer0-infra.com`）を入力
3. 本人確認書類のアップロード（運転免許証・マイナンバーカード等）
4. 振込先の銀行口座を登録（個人名義の口座でよい、法人化不要）
5. 審査完了を待つ（数分〜数営業日）
6. ダッシュボードで商品を作成
   - 商品名: 「入札情報ウォッチ」（v0.14で改称。旧称「入札情報通知Bot」は使わない）
   - 価格: 月額3,000〜5,000円程度（セルフサーブ帯の推奨レンジ内。初期は仮価格でOK、テスト運用で調整）
   - 請求サイクル: 月次（Recurring）
7. 「Payment Links」機能で支払いリンクを発行（コード不要）
8. まずテストモードで一通り動作確認してから本番モードに切り替える
9. 発行されたリンクを教えてもらえれば、LPの料金カードへの組み込みはClaude側で対応する

### PayPay等の他決済手段について（2026-07-11検討・見送り）

PayPayにも「継続課金API」自体は存在するが、加盟店審査が**対面販売（実店舗でのQRコード決済）を前提**にしており、個人事業主の申込みには店舗写真の提出が必要。通信販売のようなインターネット主体の販売形態は審査に通りにくい傾向があるとされ、本サービス（完全オンラインのサブスク、物理店舗なし）とは相性が悪いと判断し見送り。StripeはオンラインSaaS課金が主戦場でこの制約がないため第一候補とする。実際に「PayPayでも払いたい」という要望が来た時点で改めて検討する。

## Claude側で対応可能な作業

- Stripeアカウント作成後、Webhookで「支払い完了」イベントを受け取り、DynamoDBの購読者テーブルに自動登録する仕組み（Lambda + API Gateway）は実装可能
- ランディングページ（申込みページ）の作成
- 通知メール配信対象を「購読者テーブルに存在するメールアドレスのみ」にする拡張

## 現状（MVP段階）

現時点ではまだ有料課金を開始しておらず、収集・通知パイプラインの動作検証が優先。Stripe連携は「実際に顧客に販売する」フェーズになってから着手する。
